## 数量与边界

- 21 题：`gbits-069`–`gbits-089`；16 单选、2 输出填空、3 编程；`order` 247–267。
- 单选配额：C/C++ 5；数据结构 4；系统/网络/数据库模型 3；数学 3；客户端数学 1。题库没有数据库分类，数据库模型题使用已有算法分类与明确数据库标签。
- 证据分布：11 题 `历年考点·原创变式`，10 题 `预测考点·原创训练`。每题题干、tags、sourceTitle、sourceUrl 和解答均给出边界。所有题面、选项、输入约束、样例、代码是本次原创。
- 标签的历年身份只指来源明确可见的考点类别；没有声称原创条件、代码或样例在历年出现。087 的超 64 位、符号/负零；088 的一次半伤护盾均单独写明为预测拓展。
- 2024 亲历只明确“两道输出题”，没有公开原程序，因此 085/086 虽参考这个题型，**具体考点标预测**。070 指针距离、073 switch 贯穿、077 加权最短路也保守标预测，避免把“见过数组/树/短程序”当具体命中证据。

## 来源核查

- 历史源台账：`docs/GBITS_EXAM_STYLE_AUDIT.md`；其中 2017/2018 重复样本不当作独立命中频次。牛客缺失公式/图片/代码不补写为史实。
- [2024客户端亲历](https://www.nowcoder.com/feed/main/detail/5740c288da3140d3878f04dc3382073e) 本轮重新读取全文：仅支持题型结构、进制比较、右/下资源网格等大类。
- 技术按一手资料复核：[C++参考草案引用](https://eel.is/c++draft/dcl.ref)、[range for](https://eel.is/c++draft/stmt.ranged)、[switch](https://eel.is/c++draft/stmt.switch)、[静态局部量](https://eel.is/c++draft/stmt.dcl)、[指针运算](https://eel.is/c++draft/expr.add)、[整数除法](https://eel.is/c++draft/expr.mul)；规则均以 C++17 实跑对应程序确认，未把有符号溢出或UB写成确定输出。
- [RFC 9293](https://www.rfc-editor.org/rfc/rfc9293.html) 的 SND.UNA/SND.NXT/SND.WND、usable window；[OSTEP 调度](https://pages.cs.wisc.edu/~remzi/OSTEP/cpu-sched.pdf) 的非抢占SJF与抢占STCF/SRTF区分。
- Princeton《Algorithms》作者资料的[堆](https://algs4.cs.princeton.edu/24pq/)、[非负加权最短路](https://algs4.cs.princeton.edu/code/javadoc/edu/princeton/cs/algs4/DijkstraUndirectedSP.html)、[散列表实现](https://algs4.cs.princeton.edu/code/edu/princeton/cs/algs4/LinearProbingHashST.java.html)、[BFS资料](https://algs4.cs.princeton.edu/lectures/keynote/41UndirectedGraphs.pdf)。初次 direct open 部分返回403，随后通过搜索索引实际读到作者网页/代码/讲义相关段落，不将错误页当已读证明。
- [Unity反射向量](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Vector3.Reflect.html)、[PostgreSQL B-tree](https://www.postgresql.org/docs/current/btree.html)、[GMP大整数概念](https://gmplib.org/manual/Integer-Functions)。087实现是手写vector，不依赖GMP/Boost；080只使用题面自定义容量模型。089滑窗正确性由本解答不变量证明及独立子串枚举支撑，未引用无关BST材料作为滑窗依据。

## 实际检查

```bash
python3 scripts/gbits-sprint/verify-b.py --negative-probes
```

实际输出：

```text
PASS paper B: 21 metadata; 7 C++ output programs; 11 independent DS/math/system checks; algorithms 087=1805, 088=553, 089=3781; samples=3; negative probes=6; compiled=14
```

脚本每次**读取实际 JSON 中的题干/参考答案代码**，不另抄一份参考实现；`--paper <path>` 可校验待合并副本。编译器为本机 `clang++ -std=c++17 -O2 -Wall -Wextra`。正常程序10个（7输出、3算法），加4个需编译的负向探针共14次编译，另外2个答案故障探针不需编译。所有算法样例也从实际题干抽取执行。

负向探针均仅改临时副本：错误加权图答案、错误SRTF答案、错误填空答案；负数长整数不反转大小；DP护盾不减伤；滑窗左边界可回退。六个均被正向检查器拒绝。恢复后正向检查再次全通过；测试不写生产题库或学习记录。

独立建堆核算抓到初稿把最后两个叶子位置写反的问题，已修正选择项/解析/评分点并重新跑全套。该记录用于说明核验确实能抓错，不表示其他题仅凭看代码判对。

## 集成查重修订

主代理交叉核看发现初稿077与C卷BST后继题实质重复、078与A卷非抢占SJF过近。现已保留ID与正确字母，077改为5点6边的非负加权Dijkstra最短路（预测），078改为明确可抢占的SRTF；对应题干、所有答案副本、标签、来源、评分点、独立oracle和本台账同步。两题分别通过Floyd/全部简单路、逐单位抢占模拟核验，新增错误答案探针确认检查能抓错。未改共享题库，须由主代理重新合并这两个ID。

最终独立复审将078 SRTF降为预测，避免把调度大类当已确认的具体抢占算法。最终11历史、10预测。
