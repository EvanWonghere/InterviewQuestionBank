# 题目质量与练习约定

每题只测一个主目标，题干给清平台/版本/前提，避免“请全面介绍X”。参考答案需要包含可闭卷复述的机制、逐项评分点、易错反例、最小验证和可追溯资料。个人真实面试反馈只记录用户明确提供的主题，不杜撰公司、日期或原题逐字稿。

本次补充 q-149–q-178：UI空间7题、构建产物与排错6题、操作系统基础与场景5题、引擎原理12题。用户明确反馈的缺口是UI空间、打包产物和操作系统作用，细分题目是据此编写的训练变式。

## 每日练习

先提交自己的答案再看解析；提示后答对与闭卷独立答对分开记录。缺核心评分点选“重来”或“困难”，不要因为看懂答案就选“良好”。题库复习队列管理间隔；Resume的两周计划负责选题，CSV只登记时间和评估证据，不复制答案。

基础题60–90秒解释；场景题3–5分钟说明证据和排错路径；工程练习可拆成20分钟子目标。完成一次延迟闭卷复测，再换输入/平台/约束做变式。

## 来源与维护

优先Unity/Android官方文档和OSTEP教材。已核验的旧版Windows清单用于说明文件角色，不能当Unity 6每个后端的固定清单。题目ID保留以兼容笔记和进度；标签用于选题，不代表题目被某公司真实问过。最小验证是练习要求，不表示作者已在所有平台实测。
